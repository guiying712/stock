# NEXT05 通知窗口聚合与流量控制

本页保留NEXT05当次的模块/fake验收记录：当时未接入常驻worker、未重建wheel。后续[NEXT04本地模拟调度](next04-dispatch-lifecycle.md)已完成独占生命周期及worker/守护接线，并重建本地wheel；真实机会渠道和目标群仍未验收。下文非模拟标记等约束描述真实渠道，模拟渠道另保留原输入标记，不改变历史验证结论。

## 分组与范围

策略使用当时可见、有效的成员集合计算板块Jaccard相似度。达到阈值的相似关系形成连通组，以组内最小板块ID为组号；定义版本为`jaccard-connected-v1:<feature_version>`。因此A-B、B-C达到阈值时，A/B/C归为同组；不合并板块原指标、分数或独立信号。空成员板块不因分母为0与其他板块合并。

首次从DETECTED进入PREALERT或CONFIRMED时，在信号及事件快照的`evidence.notification_group`保存分组ID和版本哈希。哈希包含分组定义版本、同组板块ID及各自成员集合，成员变化会得到不同版本。已发episode的分组随原触发证据冻结，后续成员变化不重写它。

聚合键为`策略版本 + 首次trading_date + 分组ID + 分组版本`。不同版本、首次交易日或成员版本隔离；不会只根据相同板块名称合并。旧信号缺冻结分组证据时保持单条通知，不用今日成分回填。

## 窗口与投递

调用方须在保存SignalEvent的`BEGIN IMMEDIATE`写事务中调用`enqueue`。每个信号/修订/渠道继续拥有独立outbox记录；不修改旧载荷、事件或业务ID。

新机会读取已保存完整配置中的显式`runtime.group_window_seconds`：0关闭聚合，1至59秒开启；缺配置直接报错。窗口从首条入队UTC时间开始，截止时间保存在每条`payload.aggregation.ready_at`。后续成员使用该窗口原截止时间，恰在截止时刻入队的消息进入下一窗口。首条被取消后，其原记录仍作为未结束窗口的锚点，存活成员不延后；重启后从数据库继续。

例如窗口5秒：t=0入队A；t=2旧修订A被取消；t=4入队同组B；t=5调用投递器即可发送B。窗口不因后到消息、取消首条或重启滚动延长。

`dispatch_pending(store, notifier, as_of, max_messages=20)`不等待、不创建后台线程。调用方在截止后再次调用才会投递；配置窗口只限制聚合收集等待，调度停机、限流、网络或重试还可能造成额外等待。不能据此声称真实平台P95时延已通过。

到期发送前逐条复核模式、非模拟标记、修订、状态、质量暂停、价格范围、TTL和报价新鲜度。旧修订或不合格成员单独变为expired并记录原因，其余成员继续发送。正文保留每只股票的触发/最新价格与时间、规则分、参与范围、结构位、版本、信号ID和来源，分数仍不表述为胜率。

确认/恢复等后续更新保持单条，不等待聚合窗口；失效、过期、条件暂停和偏离等风险更新单条优先。每日新机会额度不会屏蔽风险更新，渠道物理限流仍适用。同一信号有sending请求时，后续修订暂缓领取，避免本地并发开始顺序倒置；无法承诺平台侧最终受理顺序或端到端exactly-once。

## 事务、重试与限流

- 在一个短事务中将本次请求全部成员标记sending并写入开始记录，事务外调用notifier，再在一个事务中回写每个成员结果。网络调用期间不持有SQLite写锁。
- 每个成员的开始记录保存共同`delivery_id`、`notification_ids`、发送时`dispatch_snapshot`和规范JSON的`message_hash`。保留原触发载荷；最新价格可以追溯到该次发送快照。
- 明确失败按30/60秒退避，每条通知最多三次发送。仅原批次仍有效的成员共同重试，新机会另成批次；取消的旧修订不重发。
- 超时、调用异常或崩溃恢复后，所有相关成员为unknown，均不自动重试。恢复仅由取得独占dispatcher所有权的启动流程执行。
- 聚合正文按原适配器18,000字节限制拆分；不截断股票证据。单条仍过长时取消为MESSAGE_TOO_LARGE，不调用notifier。
- 同数据库钉钉渠道每滚动60秒最多20个实际请求。按共同delivery_id去重计数，旧尝试记录无此字段时仍按单次请求计数；跨进程/重启共享限制。
- `max_messages`是一次调用的请求数上限，返回结果按成员列出，可能超过此数量。HTTP健康与通知API仍按通知记录计数，不能将其当作请求数。

## 模拟验收

测试均使用临时SQLite和Mock/fake notifier，模拟时钟固定，无真实Webhook、行情请求或群发送。

| 用例 | 证据 |
|---|---|
| 多股票合并与逐条证据 | 两只不同股票一次send，原载荷不变；发送快照保留最新价，各成员可查询结果与尝试 |
| 固定截止与重启 | 4.999秒不发送、5秒发送；4秒后到不延长，5秒边界另开窗；取消首条及重启仍守原截止 |
| 分组一致性与冻结 | 链式相似形成稳定组、输入逆序结果一致；成员变化版本不同，原episode快照保持不变 |
| 风险优先 | 未到期或已到期的新机会均不阻挡风险；质量暂停取消普通机会但仍可发送风险更新 |
| 逐条取消 | 旧修订、价格偏离、TTL、陈旧行情和参与暂停分别保留原因；其他成员仍可发送 |
| 分组隔离与兼容 | 策略、首次日期、热点和成员版本不同不混合；0窗口与缺旧证据维持单条；缺参数报错 |
| 超长消息 | 拆成多个不超过上限的请求，各正常成员只出现一次；单条过长明确取消 |
| 明确失败 | 只重试原组存活成员，不吸收新机会，遵守原退避和尝试次数 |
| 不确定与崩溃 | 聚合超时所有成员unknown；领取后中断可恢复，成员列表保留，不自动重发 |
| 并发顺序 | 同一批次只领取一次；网络调用外可写数据库；sending期间同信号后续修订不越过 |
| 事务故障注入 | 第二成员领取失败时整批回滚且不调用网络；第二成员结果回写失败时整批保留sending，恢复为unknown而不重发 |
| 流量控制 | 40条通知组成20个请求可一次受理；第21个请求受限；重启共享额度，滚动60秒边界恢复 |
| 正文安全 | 聚合保留转义、模拟提示与北京时间，不@全体、不把来源字符串当成Markdown链接 |

完整测试及时间以[验证记录](verification.md)的NEXT05追加条目为准。未做真实群消息渲染、授权行情、全市场负载或常驻端到端时延测试；后续接线须保留发布门槛。
