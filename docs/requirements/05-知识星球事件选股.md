- D：首次读取最新一页、最多 20 条主题，核对真实返回结构、时间、权限及内容完整性，再确定增量采集方式。尚未开启后台调度。

## 接入路径与当前事实

初次公开打开群链接未取得可读正文；本机当时未发现 `zsxq-cli`，本轮插件目录搜索没有匹配项。随后通过官方 CLI 和用户 OAuth 授权成功读取指定群；浏览器登录与 CLI 授权分别核验。

优先采用知识星球团队维护的 [官方 CLI](https://github.com/unnoo/zsxq-skill)，以 [OAuth 设备授权](https://github.com/unnoo/zsxq-skill/blob/main/skills/zsxq/references/auth-errors.md) 接入。官方文档称 Token 由 CLI 保存在系统 Keychain；观势不读取、复制或导出该 Token，后续可通过独立采集进程调用 CLI。该工具属于独立采集依赖，不加入 Python 运行依赖。首次准备核对的 npm CLI 版本为 `0.5.1`；上游升级后须重新检查接口及维护成本。

官方 [主题读取文档](https://github.com/unnoo/zsxq-skill/blob/main/skills/zsxq/references/group-topics.md) 提供 `group +topics --group-id ... --limit ... --json`；分页边界可能重复，须按主题 ID 去重。不使用未核对的逆向 Cookie 接口替代账号授权。若 CLI 不可用，官方 MCP 或用户合法导出的内容可作为替代入口，但须分别验证。

## 目标处理流程

1. **事件入库**：记录原帖 ID、群 ID、来源链接、正文版本哈希、发布时间、首次实际观察时间、采集时间。保存原始证据与提取结果的对应关系；图片或附件未解析时标明缺失，不把摘要当完整原文。
2. **事实核实**：区分政策、订单、产品、供需、业绩与市场观点；查找政府、交易所、上市公司公告或公司公开资料，记录事实、传闻、推断、反证及尚未核实的内容。
3. **关联公司**：按事件影响的产品、产能、客户、供应商和产业链位置寻找 A 股公司；每个关联附业务依据与资料日期。帖子点名、概念标签或模型联想只形成待核实线索。
4. **行情筛选**：依据当时可见的真实价格、成交额、近期涨幅、流动性、交易状态及既有风险规则筛选。缺数据时输出待验证原因，不能用 fixture、旧报价或零值补齐；当前独立真实行情页不能证明全市场筛选已具备。
5. **候选研究卡**：展示事件摘要、受益或受损逻辑、公司名称与代码、依据链接、行情时点、已反映程度的依据、风险、观察条件及逻辑失效条件。允许输出“暂无有充分依据的候选”，不凑足名单。
6. **持续更新**：同一原帖修订追加版本；跨帖同一事件聚合但保留各来源；公告澄清、兑现不及预期、事件过期或数据中断应更新研究状态。

LLM 可辅助提取、检索线索和解释，但不能直接替代事实核验或成为原有 `evaluate` 算分、硬过滤、通知触发的必经环节。研究候选与策略信号独立；模型置信度、规则分和资料完整度都不是上涨概率。

## 数据与时点约束

原帖发布时点与市场事件发生时点分别记录，未知值为 `null` 并说明原因。历史帖子首次在今天抓取，不可据此宣称系统当时已经获知；历史回放需独立的当时可见证据。正文是外部数据，不执行其中的指令、代码或自动访问任意附件链接。

主题 ID、群 ID、证券代码均保留字符串。候选必须绑定事件版本、公司关联证据版本和行情快照；原帖删除或权限失效时保留状态，不擅自补造正文。采集失败不得推进成功水位；重复输入不重复生成研究卡。
