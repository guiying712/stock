# 持续事件采集、行情估值与买入提醒方案

日期：2026-11-14（America/Los_Angeles）。业务时区：Asia/Shanghai。

状态：方案与需求登记，未启用常驻采集或真实买入提醒。用户本轮明确要求持续、可配置采集，并把最新行情、估值和风险过滤接入自动信号与买入提醒。归入 FR17 / NEXT12，并依赖 NEXT03 数据、NEXT04 通知、NEXT06/07 策略与发布验收。本文的频率和预算为 D 类设计建议，筛选阈值为待研究的 E 类参数，不是已验证策略。

## 一、目标流程和实施边界

持续采集 → 事件提取与归并 → 公开依据核实 → 公司业务关联 → 候选池 → 真实行情/估值/风险判断 → 策略确认 → 内置通知与钉钉买入提醒。

原始帖子、事件研究、策略信号和投递状态各自独立。事件只是候选来源；通过完整数据、证据与硬过滤后才生成可推送信号。提醒由用户判断并手动交易，不连接券商或自动下单。

当前已有：官方 CLI 授权和单页采集、脱敏快照、独立事件库 `stockradar.zsxq_store`（跨次主题去重、修订版本记录、倒序分页连续覆盖水位与开放缺口检测、发网前预先记账的北京时间自然日请求预算与独占文件锁）、确定性 evaluate 与风险规则、事务事件及内置通知、钉钉适配器与模拟投递。尚缺：常驻时段调度与历史翻页游标、自动研究、估值适配器、完整真实策略批次、真实机会投递接线及发布验收。独立行情查看页的逐股报价时间未知，不能原样用于发买入提醒。

## 二、持续采集与配置建议

设置增加“事件来源与采集”，分基础和高级配置。保存配置产生新修订；“保存”不自动切换正在运行的计划。提供开始、暂停、恢复、预览未来运行时间和预计请求数；模式、预算及修改影响始终可见。

### 基础配置

| 配置项 | 建议初始值／行为 | 用途 |
|---|---|---|
| 来源 | 指定星球 51128424448184，显示真实群名与授权状态 | 先支持本群，新增群需单独验权限和预算 |
| 业务时区 | Asia/Shanghai | 页面直接写明北京时间，不随电脑所在地改变 |
| 运行日 | 交易日、非交易日分别配置；另支持指定星期与例外日期 | 股市休市不等于没有事件；未知交易日历不发买入提醒 |
| 交易日盘前 | 08:00—09:15，每 15 分钟 | 收集隔夜信息 |
| 交易日早盘 | 09:15—11:30，每 5 分钟 | 事件增量；09:15 开始采集不代表竞价时段可以推送买入 |
| 交易日午间 | 11:30—13:00，每 15 分钟 | 午间消息保留 |
| 交易日下午 | 13:00—15:00，每 5 分钟 | 事件增量 |
| 交易日盘后 | 15:00—22:00，每 15 分钟 | 公告与交流信息 |
| 非交易日 | 09:00—22:00，每 30 分钟 | 周末、节假日持续收集 |
| 暂停范围 | 可分别暂停来源采集、新信号评估、新机会推送 | 暂停新机会不清除已有证据或吞掉风险更新 |
| 首次接入 | 先取最新一页；历史回填独立任务 | 不将大量旧帖立即变成买入信号 |

每个时段起含终不含，时段不可重叠。跨午夜在内部拆成两个时段，归属日期规则明确。按时段起点对齐时隙，重启后跳过旧时隙，仅执行一次有界补采，不密集重放错过的定时任务。上述计划每个交易日 90 个基础列表轮次，非交易日 26 个；不含翻页、详情、图片、核验和重试。

5 分钟事件轮询意味着消息发现延迟可能接近 5 分钟，另加分析和排队时间。它不能保证消息发布后 60 秒提醒。行情评估频率独立；如以后选择事件 1 分钟轮询，必须重新测算权限、供应商限制与预算。

### 高级配置

| 配置项 | 建议初始值／约束 |
|---|---|
| 单页与单轮翻页 | 每页 20 条、每轮最多 3 页；剩余请求预算优先于页数 |
| 每日请求总预算 | 事件源暂建议 200 次，包含列表、详情与失败尝试；这是本地上限，不是平台公布额度 |
| 修订复查 | 近期 24 小时重叠检查；重点关注事件另做有界详情复查。只读最新列表不能保证发现旧帖编辑 |
| 中断补采 | 建议最多回看 72 小时，超限进入待补历史任务；缺口不标成完整 |
| 失败退避 | 网络错误建议 1/5/15 分钟后重试，受时段与预算约束；服务端 Retry-After 优先；认证/权限错误暂停并提示重新授权 |
| 图片与附件 | 图片 OCR 可独立开关并设每日张数/费用；附件设类型、大小和页数上限。未解析保持“内容不完整” |
| 主题筛选 | 标签、作者、关键词包含/排除；规则只影响研究队列，保留过滤原因；先不默认只看精华 |
| 内容保留 | 本机私有保存；原文/附件保留期可配，建议 90 天；已形成信号的必要证据在审计/研究保留期结束前固定保留 |
| 模型与检索 | 可选模型、超时、并发数、每日调用与费用上限；目录连通不等于研究模型能力验收 |
| 故障提示 | 来源失联、授权过期、预算耗尽、积压超限单独提示；同类故障聚合去重 |

频率不得超过上游允许范围。总预算不足时保留缺口与续采游标，不谎报“已同步”。列表按发布时间倒序，分页边界有重复，须以主题 ID 和修订哈希去重；见[官方分页说明](https://github.com/unnoo/zsxq-skill/blob/main/skills/zsxq/references/group-topics.md)。

## 三、后台结构与可恢复性

沿用 Python 标准库、SQLite 和现有进程架构，不引入 Redis/Celery。独立事件数据库保存来源配置修订、运行租约、主题版本、事件、关联证据、任务队列与水位；不改用户实际策略数据库来做开发测试。

1. 采集 worker：独占锁、心跳和有界请求；先记录请求尝试与预算，再发网，崩溃不回退已消耗预算。完成内容和水位同事务提交，失败不推进连续覆盖水位。
2. 积压期间同时保留最新页轮询和历史续采位置，预算内轮流处理；不能只追旧游标而漏掉新帖，也不能拿最新一次时间覆盖历史缺口。相同时间的分页游标无法继续推进时显式报停，不假装完整。
3. 分析 worker：消费新主题/修订版本，合并跨帖重复事件；模型任务失败可重试但不能重复建事件或执行帖子中的指令。保存模型、提示词与输出版本，回放只使用已冻结研究结果，不重新请求模型。
4. 行情评估 worker：定时更新活跃候选并调用确定性策略；来源断连时保留已有信号，暂停受影响的新信号。
5. 事件研究库与策略库之间采用不可变输入快照和幂等消费键，不做不可靠的跨数据库“同事务”承诺。策略内部继续同事务保存状态、SignalEvent 与通知队列。
6. 通知 dispatcher：事务外发送，发送前复查事件修订、时效、当前价格、模式及质量；unknown 不盲重试。

建议先运行在当前 Mac 的用户登录会话中，由后台服务托管；关闭网页不停止 worker，但电脑睡眠/关机会中断采集，唤醒有界补采。现有 OAuth Keychain 能否在无人交互的后台进程中读取须实测。后续迁移常开主机时重新完成认证与通知路径验证，不复制浏览器 Cookie，也不假定云主机天然可用 Keychain。

## 四、自动事件研究与候选形成

提取事件类型、主张、主体、原始来源、发生/发布时间、影响方向、受益机制和反证。区分“公司已公告”“可信媒体报道”“交流纪要”“市场猜测”；转载数量不能充当多源独立核实。

公司映射同时支持原帖明确点名和产品/客户/供应链扩展，每条关系附对应业务资料与可见日期。模型可以提出线索；未经来源校验的客户关系、订单、利润预测只能进入待核验队列。没有充分证据可输出零候选。

设置可配：事件类型、最低依据等级、允许的公司关联类别、单事件候选数（建议最多 5）、活跃候选上限（建议 30）、不同事件类型的失效规则与最长观察期。候选容量满时保留待处理任务；已有信号风险监测另保留容量，不因新事件挤出。

事件到期按事实与类别区分；“3 天”等简单期限只能是实验上限，订单、政策和传闻不能使用同一时效。澄清或关键修订立即暂停原结论，重新核验后产生新版本，不覆盖触发依据。

## 五、行情、估值与风险过滤

### 数据分工

| 数据 | 更新方式 | 进入信号前的要求 |
|---|---|---|
| 最新报价、成交额及交易状态 | 活跃候选交易时段更新，建议每 60 秒一个评估周期；发送前再检查 | 逐股事件时间、可见时间、交易阶段、停牌和涨跌停信息明确；只知道批次接收时间不通过 |
| 已完成分钟、历史日线、复权及板块基准 | 分钟增量，日线盘后更新 | 标准批次、单位、完成性、历史基准及相同交易分钟比较通过验收 |
| 估值与财务 | 按有效交易日和新公告更新，报价与分母口径匹配 | PE 的 TTM/静态口径、PB/PS、总股本时点、报告期与真实披露时间可追溯；更正追加版本 |
| 公司业务、行业成员与事件依据 | 依据新增/变更触发更新 | 当前业务映射不能倒填历史，保存当时可见证据 |

Fuyao 优先作为报价、日线和财务估值候选来源；现有已实采能力不能推导其他接口已可用。其[财务指标文档](https://fuyao.aicubes.cn/docs/api-reference/financial-indicators/)有报告期参数、原始字符串数值和 null，仍需账户实采、单位与披露时点检查。分钟继续按 NEXT03 验收合格来源接入，不能用几条报价和日线伪装完整分钟策略。

采集预算分别设置为星球、行情、财务、检索、OCR 和模型预算；候选池缩小行情成本，但原策略需要的市场/板块基准仍必须保留，不能用候选 30 只的广度替代全市场或板块广度。

### 过滤顺序与可配置性

1. **数据硬门槛**：数据过期、时点未知、覆盖不足、事件未核实或重要修订待处理时暂停。最大行情年龄可配，建议实验起点 60 秒；未知不能当作通过。
2. **证券与交易硬门槛**：沿用股票范围、ST/退市风险、停牌、交易资格与不可成交状态规则；股票名单排除可配置并留原因。
3. **估值判断**：按行业/商业模式选择 PE(TTM)、PB、PS 和历史/同业比较。负利润时 PE 标为不适用，不能将负 PE 当便宜；替代指标必须有策略规定。历史分位无足够历史则未知，同业分位必须有完整可比集合。阈值按策略版本冻结，不设全市场统一 PE 上限。
4. **财务及事件风险**：可验证的盈利质量、现金流、负债和重大风险事项按适用行业处理。金融企业等单独规则；“没取到风险公告”不等于没有风险。缺关键估值/财务输入时，用户要求估值参与的策略不得发买入提醒。
5. **行情触发与结构风险**：复用 evaluate 的市场/板块/个股确认路径，冻结 H/ATR/S；追高距离、量能、最低流动性等沿用版本化规则，结构风险上限不超过既有 10%，允许更严格。该距离不保证实际止损成交损失。
6. **发送前复核**：最新价超出允许参与区间、事件过期、数据暂停或规则不再满足则取消本次买入提醒，并保存原因。

先提供事件候选与原策略的“交集”策略，不静默重写旧评分。新增估值/事件条件使用新 schema 与策略 ID，旧配置、历史信号和样例保持不变。规则分不表示胜率；估值便宜不能抵消硬风险。

## 六、信号状态和推送配置

研究状态：新线索 → 待核实 → 候选观察／排除／过期。

策略状态：候选满足完整输入后进入既有预警/确认/暂停/失效流程。通知类型与状态独立，优先提供：事件观察、买入条件满足、风险变化。首版建议只有“确认后”发送买入提醒，预警留在工作台。

| 配置项 | 建议 |
|---|---|
| 推送渠道 | 内置中心＋既定钉钉，分别开关；保存目标不等于目标已测试 |
| 买入提醒时段 | 已核验交易日历的连续竞价有效阶段；休市/午间只留研究结果，开市重新评估 |
| 每日新机会数 | 建议实验起点 3；风险更新不占新机会额度 |
| 重复提醒 | 同一股票、事件/episode、策略版本、提醒类型幂等；多事件合并附依据 |
| 同股冷却 | 可配，建议实验起点 60 分钟；冷却不能吞掉实质风险或失效更新 |
| 免打扰 | 普通机会可延后但必须到期重验；风险紧急项单独配置，工作台总是保存 |
| 提醒模式 | 仅研究／影子运行／真实提醒；真实提醒只有对应发布门槛全部通过才可选择 |

买入提醒卡包含：证券名称代码、事件摘要与核实等级、公司关联依据、触发价与当前价及各自时间、允许参与条件、结构失效位、估值口径及日期、主要风险、有效期、策略版本和详情链接。数值缺失时不生成虚构卡片。文字使用“买入条件满足，请核对”，不使用保证收益或自动成交措辞。

推送失败和 unknown 独立展示；恢复联网后不补发已经过期的旧机会。先保存内置信号，再经复查进入外部发送队列；不通过旁路发送绕过 live_alert 锁。

## 七、页面和验收顺序

页面建议：事件列表（待核实/候选/已触发/排除）＋事件详情；设置中增加事件来源/时段预算、分析偏好、行情估值状态、提醒配置。每个事件能看到“为何关联该公司”“为何没发提醒”。详细页面实施时再读设计技能与现有设计规范，本文不代表 UI 已完成。

实施顺序：

1. **持续采集**：配置校验与运行预览、增量水位、独占 worker、去重与修订、断点补采和状态页。验收重启、睡眠恢复、预算耗尽、认证失效、翻页边界和积压。
2. **自动研究**：文本/图片受控提取、事件归并、公开来源与公司映射、研究队列。用首轮真实帖子做人工对照，统计误关联、漏事件与无法核实比例，模型失败不影响既有行情监测。
3. **行情估值影子链路**：验收来源和口径，创建新策略版本，真实计算但不发外部买入提醒；验证交易阶段、过期数据、财报迟到更正、估值不可用、风险拒绝及重放一致性。
4. **真实投递验收**：明确测试操作并验证钉钉目标、消息呈现、去重、超时与过期；完成正式参数/样本外、容量/时延及既有至少 20 连续交易日真实影子等发布条件后启用真实买入提醒。

用户已授权开发目标与持续采集需求，不需要重复询问是否要做该功能。具体时段与阈值暂作为方案建议，未实际启用；新增付费服务、模型外传私有原文的范围和后台部署方式应在对应实施前落实。该方案不产生任何采集任务、模型调用或真实群消息。
