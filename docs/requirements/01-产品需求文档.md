# 产品需求文档：A 股热点启动与突破提醒

版本：v0.1｜2026-10-28｜适用：个人单用户首版。

实现状态补充：已交付软件`0.2.1`离线增强版，含PoC报告、分钟K线、页面成本研究及供应商原始小样本工具；已取免密日线，尚无已验证可供策略使用的分钟行情商。用户确认钉钉渠道。本文保留目标需求和发布门槛，已实现/未验收项见[交付验收](../development/acceptance.md)与[当前进度](../../TODO.md)。

## 1. 目标与成功定义

持续观察沪深主板、创业板和科创板，通过市场环境、板块启动和个股突破发现短期候选机会，在交易时段及时通知用户。用户自行交易，软件保存每次判断依据、状态变化和后续表现。

“最值得投资”在首版中的操作定义是：在指定策略、观察时点和风险条件下，通过硬性过滤的候选中优先级较高的机会；不宣称全市场最优或确定盈利。

成功分为两层：

- 工程成功：数据可信、信号可重放、通知及时且可追踪、故障可见。
- 策略验证：在未用于调参的时间段，比较成本后表现、不利波动、可参与性和失败率；是否有价值必须有证据，不预设收益率或胜率。

## 3. 范围与优先级

### P0：第一版必需

全市场合格股票池、交易日历、行情接入与质量检查、市场状态、行业/题材热点识别、突破策略、动态标签、可解释评分、信号状态管理、内置通知中心、一个外部通知渠道、历史回放与评估、运行监控、参数版本管理、基本信号反馈。

### P1：基础链路稳定后

轻量持仓与亏损提醒、更多通知渠道、盘后信号复盘摘要、可选 AI 解释、公告/业务关系核验。

### 不在第一版

自动下单、券商凭据或账户同步、完整会计账本、杠杆/衍生品、北交所/港美股、全产业链本体、复杂多 Agent 辩论、深度预测模型、自动调参后直接上线、多用户商业平台。

## 4. 核心用户流程

1. 初次配置数据源、扫描范围、策略版本与通知渠道，完成连通性诊断。
2. 盘前加载股票状态、历史行情、板块成分和预先确定的突破参考位。
3. 交易时段按行情切片更新市场与板块状态，筛选突破候选。
4. 通过硬性过滤、评分门槛、当前有效性和去重检查后推送。
5. 用户从手机通知打开信号详情，看到触发快照与当前状态；可标记观察、忽略或已买入。
6. 信号增强、失效或过期时更新；用户未买入也保留信号结果。
7. 盘后归档全部候选、被过滤原因、通知记录与结果；到期计算未来表现。

核心路径不依赖用户一直打开页面，也不依赖 LLM 在线。

## 5. 功能需求与验收

| ID | 功能要求 | 最低验收条件 |
|---|---|---|
| FR01 | 全市场合格股票池；保存过滤原因和历史状态 | 覆盖沪深主板、创业板与科创板；科创板合格证券纳入覆盖率分母，仍按相同质量和风险门槛筛选；前导零保留；停牌、ST、退市整理、新股历史不足、低流动性等可排除；不能只扫描自选股却标称全市场 |
| FR02 | 行情与历史数据统一接入 | 行情含来源、单位、事件时间、可见时间、获取时间和质量；缺失不填 0；数据缺口可见 |
| FR03 | 市场状态 | 输出上涨/震荡/下跌/高波动不明及依据；不可计算时为 UNKNOWN；不由 AI 自由生成 |
| FR04 | 行业与题材热点识别 | 同时计算强度变化、广度、成交变化；板块状态可回退；一只股票不因多题材重复加分 |
| FR05 | 个股突破识别 | 突破位事先确定；量能比较使用相同盘中时段；历史不足、价格过远或质量不达标时记录拒绝原因 |
| FR06 | 标签与证据 | 标签有定义版本、对象、生效时点、来源、值、失效条件；历史标签不会被今日状态覆盖 |
| FR07 | 评分与硬门槛 | 完整输入下输出 1—100 分和分项；硬门槛失败不得靠高分补偿；无效输入评分为 null；分数不标为胜率 |
| FR08 | 信号状态 | 预警、确认、失效、过期分开；通知状态独立；重启不重复生成同一机会 |
| FR09 | 通知投递 | 内置中心＋一个真实外部渠道；记录投递尝试、响应和结果；重试前复查时效；失败可见 |
| FR10 | 去重与消息控制 | 同一股票多个题材合并；同一状态不重复提醒；风险更新不被新机会限额屏蔽 |
| FR11 | 信号反馈 | 观察/忽略/买入反馈幂等；不把点击或打开通知当作买入；忽略不从策略评价样本中删除 |
| FR12 | 回放与研究 | 历史与实时同一策略实现；只有当时可见数据；保存参数、快照和代码版本；相同输入结果一致 |
| FR13 | 运行与数据诊断 | 展示覆盖率、延迟、最后成功扫描、来源错误、通知积压；异常时明确停止或降级哪些功能 |
| FR14 | 配置与版本 | 策略版本不可原地修改；变更记录可查询；必需参数缺失不能进入真实推送模式 |
| FR15 | 持仓提醒（P1） | 有实际成交成本和剩余数量后计算浮亏；10% 风险提醒与策略失效提醒独立；卖出后停止该持仓提醒 |
| FR16 | AI 解释（P1） | 只消费结构化证据；数字来自计算结果；无法调用时使用模板，不阻塞信号 |
| FR17 | 知识星球事件与候选研究（2026-11-14 新需求） | 只读接入指定星球，保存事件与修订证据，核实公开来源和公司业务关联，结合真实行情形成候选研究卡；缺依据保持待验证，实施与验收见[专项规格](05-知识星球事件选股.md) |

## 6. 风险偏好的具体含义

- 10% 为用户单笔容忍边界，不能推导出建议仓位、账户总风险或止盈比例。
- 信号生成时，以当前参考价和策略结构失效价估算距离；超过 10% 则不作为可参与候选。无法给出有效失效位置时，不生成可参与型提醒。
- 买入后，以用户记录的实际成本计算风险；不把触发价当成真实成本。
- 策略逻辑可能先于 10% 亏损失效，应及时更新；达到 10% 也不保证能以该价格卖出。
- 首版不执行止损；交易制度、停牌、涨跌停、价格跳空和人工操作延迟必须在仿真中体现。各类交易约束按交易所官方规则、适用证券与生效日期维护，不能把所有 A 股规则硬编码成一个常量。

## 7. 通知内容与交互

每条机会包含：信号 ID、股票代码与名称、主关联热点及其他关联、策略名称/版本、预警或确认、总分/分项、触发原因、触发时间与价格、最新价格及时间、突破参考位、结构失效条件、可参与范围、数据质量、详情入口。

示意内容，非真实投资建议：

> 启动预警｜示例股票｜热点启动突破 v0.1
> 板块相对强度改善，多只成分股同步响应；个股突破预设区间，成交活跃度增加。
> 评分：82/100（规则匹配度，非上涨概率）
> 行情截至：交易所时区时间；触发价与最新价分别展示。
> 状态：初步成立，尚未充分确认；失效条件与可参与范围见详情。

规则：

1. 预警可以在板块启动候选阶段发出；无需等板块充分确认，但不得跳过数据、广度和个股入场检查。
2. 增强/失效优先更新同一通知；平台不支持修改时，发送带原信号 ID 的关联更新。
3. 同一热点多个候选可在一个短窗口合并；合并窗口不得使总通知延迟超标。
4. 超出参与范围时显示“当前已偏离”；不能一直展示“满足参与条件”。偏离不一定意味着原逻辑失效。
5. 通知服务接收成功只表示平台受理，不能写成用户已读或已成交。
6. 回调必须鉴权，反复点击不重复写入成交或反馈；无卡片回调能力时通过受保护的详情页操作。

| 市场与热点 | 数据健康、扫描覆盖、市场状态、热点状态/变化、活跃成分股 |

## 9. 非功能需求（D 类初始工程目标）

| ID | 要求与目标 | 验证方式 |
|---|---|---|
| NFR01 | 使用完成的一分钟切片；P95 从所需切片结束到通知平台受理不超过 60 秒 | 分别记录上游延迟、计算、排队与网络耗时；PoC 不满足需调整方案，不能伪称实时 |
| NFR02 | 合格股票有效行情覆盖目标 ≥98%，单板块覆盖目标 ≥90% | 分母为当时应有数据且可交易的股票；同时披露预期数量、缺失数量与行业分布；小板块另需最小样本门槛 |
| NFR03 | 过期行情、关键输入缺失时停止相关新机会推送 | 故障注入；不能用前值填充伪装实时；已发信号标记“更新暂停” |
| NFR04 | 同一输入、配置、事件顺序得到相同指标、评分与状态 | 离线重放与线上录制回放比较 |
| NFR05 | 重启后恢复已处理水位、信号和通知状态 | 分别在持久化、投递前后崩溃；无重复业务事件，外部不确定投递单独处理 |
| NFR06 | 回测重任务不阻塞盘中扫描 | 在目标机器、当前全市场规模下同时负载测试并报告内存/CPU/延迟 |
| NFR07 | 数据及凭据可保护、可备份恢复 | 日志脱敏、访问鉴权、密钥不进仓库/LLM；执行一次恢复演练 |

以上百分比和时延是初始目标，不是已验证能力；实际运行硬件、数据预算和供应商仍待确定。过期判定阈值须与切片频率一致，详见工程规格。

## 10. 验证与发布条件

研发分为离线开发、历史回放、真实行情影子运行、受控提醒四种模式。模拟消息必须显著标记，不得进入真实机会统计。

进入受控提醒前至少具备：

- P0 验收通过；至少一个合规可用的数据路径和一个通知路径经实测。
- 冻结策略与参数，完成样本外回放，公开失败信号、未成交机会和数据缺口。
- 完成建议不少于 20 个交易日的影子运行及重启/断源/投递失败演练；该窗口用于工程观察，不证明盈利。
- 说明提前预警相对确认后提醒、板块过滤相对个股单独突破的增量表现。
- 已解决数据预算、运行位置和通知渠道；用户知晓运行版本与风险表达。

若无足够分钟历史或历史板块成分，只能交付功能验证和前向观察结果，不能宣称完成可信的全市场历史回测。

## 11. 变更约束

止盈方式、组合仓位、正式评分门槛、精确突破窗口和退潮条件尚未由用户确认。研究阶段可比较不同配置，但不得把任一示例参数写成用户既定要求。

自动下单、其他交易模式或市场必须另建需求版本，不能通过“借鉴某开源项目”扩大当前范围。
