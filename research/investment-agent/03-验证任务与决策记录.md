# 验证任务与决策记录

> 历史任务与决策快照：当前范围、任务和待定项见[当前需求与工程规格](../../docs/requirements/README.md)。本文尚未决定的市场、周期等部分问题已在后续讨论中解决。

版本：2026-10-28。当前仅完成资料收集与初步设计，以下开发/测试任务均未执行。所有验收数字是拟定门槛，不是已取得结果。

## 阶段 0：补齐选型证据

| 任务 | 产物 | 验收条件 |
|---|---|---|
| 选定目标市场和券商场景 | 一页范围说明 | 明确研究市场、交易频率、是否实盘及所用操作系统 |
| 比较 Vibe-Research 与 tick-stock-panel | 两份隔离 PoC 记录 | 固定版本可启动，完成代表性流程，列出必须自建的部分 |
| 验证 a-stock-data 与 daily_stock_analysis 数据链 | 数据适配测试报告 | 按 MVP 需要选端点，保存原始样本、单位、时点、失败与切源结果 |
| 验证 TradingAgents | 一份研究编排 PoC | 结构化输出有效；可找到引用；中断恢复不重复副作用；记录成本 |
| 复用前许可与依赖检查 | 逐文件/组件清单 | 明确来源 commit、许可证、NOTICE、依赖和模型/数据授权；混合授权不跨界复制 |

数据样本建议覆盖：正常交易日、停牌、缺行情、除权、前导零代码、同代码跨市场、延迟公告、来源冲突与接口限流。样本用于工程验证，不代表选股名单。

阶段出口：确定一个应用骨架、一套数据契约、一套研究编排方案；有证据说明为何采用或不采用上游代码。PoC 失败的项目保留记录，不因 Star 多而跳过验证。

## 阶段 1：个人投研 MVP

| ID | 工作 | 验收条件 |
|---|---|---|
| M01 | 标的与自选管理 | 代码、市场与币种不混淆；导入保留前导零 |
| M02 | 数据适配与快照 | 所有核心字段附来源、单位和时间；失败不会伪装为有效数据 |
| M03 | 研究工作流 | 报告关键结论有证据链接；区分事实、推断与未知；保存模型及提示词版本 |
| M04 | 持仓账本 | 重复导入不重复记账；现金、数量、费用守恒；支持冲正和备份恢复 |
| M05 | 盘后简报 | 使用交易日历与市场时区；任务重试不重复通知；记录每次运行状态 |
| M06 | 规则选股与回测 | 冻结输入重复运行得到相同信号与交易；计入成本；禁止未来信息 |
| M07 | 可观测性 | 每次研究有 run_id、耗时、调用成本、数据质量状态和失败原因 |

阶段出口：一套可演示且可复现的个人投研流程，以及一份明确列出局限的测试报告。预算、响应时间目标在 PoC 测量后制定。

## 阶段 2：模拟交易与券商适配验证

先完成模拟订单状态机、账本、风控和恢复，再按券商约束选择 vnpy、NautilusTrader 或独立 SDK。不同时引入两套执行引擎。

必测场景：重复点击、提交超时、部分成交、乱序/重复回报、撤单失败、停牌、额度不足、行情过期、进程重启和账户状态查询失败。任何未知订单状态不得自动转成“失败后重新下单”。

建议先累计至少 20 个交易日的模拟运行，再评估实盘准备度；这只是工程观察窗口，不是收益或安全性的证明。实盘阶段还需目标券商官方接口确认、用户明确的限额与账户授权、恢复演练和对账通过。

## 阶段 3：高级策略研究

在账本、数据质量和样本外评测稳定后，独立评估 Qlib 与 Kronos；记录训练区间、模型/权重哈希、硬件、随机种子、实验次数、交易成本和基线结果。任何复杂模型必须说明相对简单策略增加了什么可验证价值。

## 开发前需要确认的产品问题

这些问题不阻碍当前资料整理，但会改变实现范围：

1. 首先覆盖 A 股、美股、港股中的哪一个？投资周期是日内、波段还是长期？
2. 第一版只做研究和模拟，还是必须接现有券商？若要接，券商、账户地区、API 权限和运行平台是什么？
3. 希望只在 Mac 本地运行，还是需要服务器常驻与手机访问？
4. 每月愿意用于行情、模型和服务器的预算范围？
5. 长期只供个人使用，还是可能公开分发/提供在线服务？这会影响代码复用方案。

## 后续资料归档模板

每次 PoC 新建 `experiments/YYYY-MM-DD-项目名/`，包含 `README.md`（目的与结论）、`versions.json`（commit/环境/依赖）、`config.example`（无秘密）、`inputs/`（有授权的脱敏快照）、`outputs/`、`metrics.json`（耗时/成本/质量）和 `failures.md`（异常与复现步骤）。

每个被复用的组件追加上游来源、精确版本、许可和本地修改记录。将敏感账户流水、真实密钥和不可再分发数据排除在公开代码仓库之外。资料刷新和策略改版后，重新运行对应验证，而不是默认为之前结论仍成立。
